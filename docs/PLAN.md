# FI — план и архитектура

Цель: приложение в трее, которое без ручной настройки возвращает нормальную работу
Discord, YouTube, Telegram, заблокированных сайтов и игр, само замечает поломки и чинит их.

Основа — опыт [zapret](https://github.com/bol-van/zapret) и
[zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube).
Их слабые места, которые мы закрываем: ручной перебор стратегий, отсутствие диагностики
«почему не работает», отсутствие реакции на поломку стратегии.

## Принятые решения (2026-09-14)

| Вопрос | Решение |
|---|---|
| Платформы | Windows → Linux. Ядро пишется переносимым. macOS/Android — позже и урезанно |
| Стек | Go (ядро-служба) + Wails v3 (трей/окно, WebView2) |
| Движок обхода DPI | winws (zapret) за абстракцией; winws2 (zapret2, Lua) — подключаемо позже |
| Туннель (sing-box, VLESS/Reality) | Отдельным этапом, опционально, сервер пользователя |
| Телеметрия / общая база | Нет. Всё локально |

## Какой механизм что лечит

| Тип блокировки | Признак в тесте | Механизм |
|---|---|---|
| DPI по SNI / протоколу | TLS reset / timeout на рукопожатии, QUIC не проходит | winws-стратегия + hostlist |
| «16–20 КБ» к зарубежным хостингам | соединение есть, передача замирает на ~16–20 КБ | ipset + fake SNI; если не помогло — туннель |
| Подмена DNS | системный резолвер ≠ DoH | DoH/DoT |
| Блок IP/протокола мессенджера | Telegram DC недоступны напрямую | Telegram WS-прокси |
| Гео-блок со стороны сайта | HTTP 403/451, страница «недоступно в регионе» | только туннель |

## Архитектура

```
┌──────── fi.exe — трей + окно (Wails, без прав администратора) ────────┐
│  окно создаётся по клику и уничтожается при закрытии (WebView не висит)    │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               │ named pipe \\.\pipe\fi (JSON-RPC)
┌──────────────────────────────┴─────────────────────────────────────────────┐
│  fi-service.exe — служба Windows (LocalSystem), автозапуск, без UAC          │
│   engine    — запуск/перезапуск winws, сборка аргументов из профилей       │
│   strategy  — база стратегий, импорт из Flowseal .bat                      │
│   probe     — сетевые проверки: DNS, TCP, TLS, 16–20 КБ, QUIC              │
│   selector  — автоподбор стратегии по группам сервисов                     │
│   lists     — hostlist/ipset, пользовательские списки, автосписок          │
│   watchdog  — периодическая проверка, тихий переподбор                     │
│   diag      — конфликты (GoodbyeDPI, VPN, Adguard, Killer, Secure DNS…)    │
│   updater   — подписанная (ed25519) база стратегий/списков                 │
│   tgproxy   — Telegram WS-прокси (этап 3)                                  │
│   tunnel    — sing-box как библиотека (этап 5)                             │
└────────────────────────────────────────────────────────────────────────────┘
```

Почему служба отдельно от UI: права администратора нужны только WinDivert; падение UI
не останавливает обход; нет UAC при каждом входе в систему; UI-технологию можно
заменить, не трогая ядро.

## Структура репозитория

```
cmd/fi-probe/        этап 0 — CLI-стенд тестирования стратегий
cmd/fi-service/      служба (этап 1)
cmd/fi/              трей/UI на Wails (этап 1)
cmd/fi-setup/        установщик и деинсталлятор
internal/engine/     абстракция движка (winws; позже winws2, nfqws)
internal/strategy/   формат стратегий, импорт .bat
internal/probe/      сетевые проверки
internal/selector/   подбор и оценка стратегий
internal/lists/      hostlist / ipset
data/                обновляемая база: стратегии, списки, цели проверок
docs/                документация, дизайн (docs/design); подробнее — docs/DEVELOPMENT.md
```

## Этап 0 — стенд тестирования (текущий)

Без точного теста автоподбор бессмысленен, поэтому начинаем с него.

`fi-probe` умеет:

1. **Импорт стратегий** из `general*.bat` Flowseal → внутренний формат (профили winws
   с плейсхолдерами `{bin}`, `{lists}`, `{game_tcp}`, `{game_udp}`).
2. **Базовый прогон без обхода** — что реально заблокировано у этого провайдера.
   Группы, которые работают и так, дальше не подбираются.
3. **Проверки на цель** (все параллельно, с таймаутами):
   - DNS: системный резолвер vs DoH → подмена;
   - TCP connect;
   - TLS 1.2 и TLS 1.3 рукопожатие с отпечатком Chrome (uTLS) — DPI может по-разному
     реагировать на ClientHello Go и браузера;
   - передача > 64 КБ (метод dpi-checkers: POST со случайными данными) → «16–20 КБ»;
   - QUIC/HTTP3 рукопожатие.
   Итог по цели: `OK`, `DNS_SPOOF`, `TCP_FAIL`, `TLS_RESET`, `TLS_TIMEOUT`, `FREEZE_16K`,
   `QUIC_FAIL`, `HTTP_BLOCKED`.
4. **Прогон стратегий**: запуск winws → ожидание готовности → проверки → остановка.
   Оценка по группам (YouTube, Discord, Cloudflare/хостинги, общие сайты); критичные цели
   (например, googlevideo) весят больше; задержка — при равенстве.
5. **Отчёт**: таблица в консоли + JSON (для этапа 1 это же станет форматом кэша подбора).

Требует запуска от администратора (WinDivert).

**Статус (2026-09-14):**
- [x] импорт стратегий Flowseal (все 22 из v1.10.2 разбираются);
- [x] проверки DNS / TCP / TLS с отпечатком Chrome / 16–20 КБ / QUIC;
- [x] классификация покрыта тестами, которые эмулируют поведение DPI локальными серверами;
- [x] оценка по группам, выбор лучшей стратегии, отчёт в консоли и JSON;
- [x] защита от одновременной работы с другим обходом (winws, GoodbyeDPI, служба zapret);
- [x] прогон всех стратегий на реальной сети пользователя (reports/run1.json): без обхода открывается почти всё,
      кроме X; лучшая — SIMPLE FAKE; «FAKE TLS AUTO» не стартовала из-за разбора `^!` — исправлено;
- [x] проверка звонков: STUN по UDP (Google 19302 — внутри фильтра стратегий, Cloudflare 3478 — контроль);
- [x] повтор после случайного сбоя; цели, не прошедшие ни в одном прогоне, не учитываются в оценке;
- [ ] повторный прогон стратегий с новыми проверками.

**Что консольный стенд проверить не может.** Скорость видео YouTube: API плеера без браузера
отвечает «Sign in to confirm you're not a bot» и не отдаёт ссылки на видеопоток. Поэтому
проверка воспроизведения переезжает в приложение (этап 1): скрытый WebView2 открывает
встроенный плеер и меряет, успевает ли буфер за воспроизведением. Голос Discord без
авторизации тоже не проверить напрямую — его заменяет проверка STUN.

## Принципы

- Никаких данных наружу, кроме запросов проверок и загрузки обновлений базы.
- Все сторонние бинарники — с проверкой sha256; обновления — только с подписью.
- Служба в простое: ≤ 30 МБ RAM, ~0% CPU. Окно не держит WebView в памяти.
- Любое автоматическое изменение видно пользователю и откатывается одной кнопкой.
